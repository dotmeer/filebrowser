# I09 — ручной чеклист панели задач

Проверки выполнялись 2026-11-05 на Windows. Интерактивный UI в браузере
вручную не прокликивался: в среде сессии нет браузерного инструмента, а
Playwright для MVP не требуется (SPEC §19). Поэтому пункты, требующие
браузерного взаимодействия, отмечены как невыполненные, а не как пройденные.

## Автоматические и HTTP-проверки

- [x] `dotnet build` — 0 ошибок, 0 предупреждений.
- [x] `dotnet test` — 92/92 на Windows и 92/92 в Linux-контейнере
  `mcr.microsoft.com/dotnet/sdk:10.0` (cross-device I08 в этом прогоне не
  включался), включая:
  - две задачи выполняются при `workers=2`, третья остаётся в `queued` до
    освобождения worker-а;
  - очистка истории удаляет только неактивные задачи и каскадно удаляет
    `task_items`/`temporary_artifacts`;
  - `GET /api/tasks/history`-поведение через `DELETE /api/tasks/history` с
    antiforgery возвращает `deletedCount` и не удаляет активную задачу;
  - `DELETE /api/tasks/history` без antiforgery возвращает `400` и не удаляет
    историю;
  - страница истории не содержит активных задач и корректно пагинируется;
  - прогресс не делится на ноль для пустого дерева, scanning/running с
    неизвестным объёмом не показывает процент;
  - подписка на серверный notifier получает уведомления, отписка их
    прекращает; DI-контейнер приложения передаёт notifier в repository.
- [x] SSR smoke `/browse?root=files`: страница содержит панель «Задачи»,
  секции активных задач и истории.
- [x] HTTP smoke на запущенном приложении: copy поставлен через
  `POST /api/tasks/copy`, завершён, SSR `/browse` отрисовывает карточку
  `Завершено` с результатом по объекту.
- [x] HTTP smoke `DELETE /api/tasks/history` с antiforgery: две неактивные
  задачи удалены (`deletedCount=2`), активных задач в сценарии не было;
  повторная очистка вернула `deletedCount=0`.
- [x] HTTP smoke без antiforgery: `DELETE /api/tasks/history` возвращает
  `400` и история остаётся на месте.
- [x] Файловый список `GET /browse` после завершения copy отражает созданный
  файл (SSR-проверка; интерактивное обновление без перезагрузки — ниже).
- [x] `docker build -t filemanager-i09 .` и контейнерный smoke test: `/healthz`
  200, `/browse` 200 с панелью, copy completed, `deletedCount=1`, `app.db`
  создан, процесс работает от `uid=1654`.

## Невыполненные браузерные проверки

- [ ] Открыть окно выбора папки назначения для copy и move; убедиться, что
  текущая папка, исходные объекты и их потомки показаны недоступными.
- [ ] Поставить copy и move из UI и увидеть карточку задачи без ручного
  обновления страницы.
- [ ] Наблюдать scanning/running, неопределённый прогресс, проценты, скорость
  и счётчики в карточке активной задачи.
- [ ] Выйти со страницы `/browse` и вернуться: подписка снимается, состояние
  снова читается из SQLite без потери задач.
- [ ] Разорвать и восстановить соединение Blazor (например, остановить и
  запустить сервер): панель после `components-reconnect-state-changed=hide`
  перечитывает состояние из SQLite; после перезапуска активные задачи
  отображаются как `interrupted`.
- [ ] Убедиться, что после завершения copy/move в текущую папку файловый
  список обновляется без ручной кнопки «Обновить».
- [ ] Нажать «Очистить историю», проверить обязательное подтверждение и что
  активные задачи остаются в списке.

Причина: интерактивные сценарии требуют живого браузера с WebSocket-сессией
Blazor; в текущей среде они не запускались.
