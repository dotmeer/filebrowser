## Текущая итерация: I07 — Исполнитель copy

### Цель

Реализовать фоновый copy с предварительной проверкой, временными объектами,
безопасной публикацией, прогрессом и агрегированным результатом согласно
SPEC §10, §13, §16 и промпту I07 в SPEC §23.

### Сделано

- Добавлен `POST /api/tasks/copy`: antiforgery, `202 Accepted`, id и
  `Location: /api/tasks/{id}`. Публичного move endpoint нет.
- При постановке отклоняются с `400/invalid_request` пустой список
  источников, корень в источниках и источники из разных родительских папок;
  заведомо провальная задача не сохраняется.
- `TaskDispatcher` дедуплицирует источники и сортирует их ordinal-сравнением
  по публичному пути; `CopyTaskExecutor` выполняет предварительную проверку
  всех источников и назначения, собирает все найденные ошибки и не начинает
  копирование при любой из них.
- Реализованы этап `scanning` с оценкой bytes/items, потоковое копирование
  файлов и каталогов, создание уникальных `.filebrowser-*` на стороне
  назначения, регистрация в SQLite до создания, публикация под конечным именем
  без перезаписи и остановка на первой фактической ошибке. Последующие
  верхнеуровневые объекты получают `not_processed`.
- Конфликт имени при copy — ошибка задачи `name_conflict`, без HTTP 409 и без
  автосуффиксов; существующие данные сохраняются.
- Прогресс пишется в SQLite не чаще раза в секунду, переходы состояний — сразу;
  скорость считается по скользящему окну 5 секунд.
- Временные объекты скрыты из листинга; любой публичный путь с сегментом
  `.filebrowser-` отклоняется `400/invalid_request` для чтения, rename, delete
  и copy. Очистка использует внутренний resolver и удаляет только точно
  зарегистрированные объекты.
- Исправлен порядок middleware: API error middleware теперь находится внутри
  generic exception handler. В Production ошибки API снова возвращаются как
  ProblemDetails с `code` и `traceId`, а не 500 HTML.
- Добавлены тесты copy между корнями, пустых папок, конфликта имени,
  конкурентной публикации, symlink, вложенности, ошибки копирования,
  сохранности данных, прерывания с остатком временного объекта, очистки только
  зарегистрированного артефакта, enqueue-валидации и Production ProblemDetails.

### Осталось

- Move не реализован и не экспонирован — это граница I08.
- UI панели задач не реализован — это граница I09.
- Linux symlink-проверки выполнены в контейнере: 5/5 и полный suite 74/74.
- Фактический cross-device move не реализован; probe выполнен, но финальную
  проверку нужно повторить на целевом NAS с двумя реальными mounts.

### Следующее конкретное действие

I08 по промпту SPEC §23: реализовать move с rename внутри одной файловой
системы, подтверждённым cross-device fallback copy + delete и честным
частичным результатом. Учесть probe: `File.Move` скрывает EXDEV встроенным
copy+delete и при ошибке копирования оставляет частичный destination, поэтому
для I08 нужен изолированный Linux rename/EXDEV-детектор либо проверка устройств
и копирование через зарегистрированный temp-объект с публикацией. Не начинать
move в рамках I07.
