## Текущая итерация: I14 — Тема оформления и возврат из настроек

### Цель

Добавить на страницу `/settings` выбор светлой, тёмной или системной темы
и кнопку возврата на предыдущую страницу, не меняя серверную конфигурацию
и файловые операции.

### Сделано

- тема оформления: палитра MD3 для тёмной темы через
  `[data-bs-theme="dark"]` в `app.css`; Bootstrap 5.3.3 использует тот же
  атрибут для `form-control`, `table`, `form-check` и `color-scheme`;
  зашитые цвета (hover/disabled/scrim/тени) вынесены в CSS-переменные;
- выбор темы: нативные радиокнопки «Системная / Светлая / Тёмная»
  на `/settings`; значение хранится в `localStorage`
  (`filebrowser.theme`), по умолчанию — `system`; режим `system` следует
  `prefers-color-scheme` и реагирует на его изменение;
- применение темы выполняется синхронным скриптом в `<head>` до отрисовки
  body — без вспышки светлой темы; страница `/settings` осталась статической
  (без Blazor circuit), переключение работает на чистом JS;
- enhanced navigation Blazor затирает `data-bs-theme` на `<html>` серверной
  разметкой; тема повторно применяется по `enhancedload`, подписка идёт и на
  `document`, и на `Blazor`, с повторным применением в `requestAnimationFrame`;
  выбор радиокнопок синхронизируется после каждой навигации;
- кнопка «Назад» возвращает по истории браузера. Проверка «предыдущая запись
  внутри приложения» использует Navigation API (Chromium), затем
  `document.referrer`, затем маркер в `sessionStorage`; при прямом открытии
  `/settings` без истории выполняется переход на `/`;
- в тёмной теме приведены к палитре reconnect-модал и полоса
  `#blazor-error-ui` (иначе светлый фон сочетался со светлым текстом);
- обновлены SPEC §9.1/§9.6, README, ручные сценарии и тест страницы
  настроек.

### Осталось / не проверено

- Визуальная проверка скриншотами не выполнялась: окно браузера в этой
  сессии не было видимым; проверка шла через DOM и вычисленные стили.
- Контраст проверен выборочно (фон/текст страниц, диалог, поля ввода,

- Автоматического теста JS-логики темы нет (в проекте нет JS-тестов);

## Итерация I13 — Интерактивная приёмка UI и фикс Docker-сборки

### Цель

Проверить интерактивный UI в реальном браузере через расширение browse,
устранить найденные дефекты, не меняя функциональность MVP.

### Сделано

- **BUG-001 (Docker/Blazor).** В контейнере `/_framework/blazor.web.js`
  отдавался 404: интерактивность Blazor не подключалась (кнопки, диалоги,
  меню не работали). Причина: `dotnet restore` в Dockerfile выполнялся при
  наличии только csproj, затем `dotnet publish --no-restore` — манифест
  статических ресурсов .NET 10 терял JS фреймворка Blazor. Исправлено
  повторным `dotnet restore` после `COPY . .` до publish (D054);
  проверено: `_framework/blazor.web.js` → 200;
- **BUG-002 (панель задач).** Уведомление об изменении задачи, пришедшее во
  время выполняющегося refresh, отбрасывалось: карточка завершённой задачи
  оставалась в «Активных», а список файлов не обновлялся после copy/move.
  Заменено на асинхронный цикл с флагом `pending`: изменения во время
  refresh гарантируют ещё один проход (D055);
- `aria-expanded` бургер-кнопки теперь рендерится как `true`/`false`;
- полная интерактивная приёмка в контейнере через расширение browse:

  конфликт имён, download (200, 221 Б, `octet-stream`, Content-Disposition),
  copy и move с выбором назначения и автообновлением панели/списка,
  удаление с подтверждением, очистка истории, контекстное меню, пустая
  папка, прямые URL и breadcrumbs, узкое окно (панели стопкой, без
  горизонтального скролла), восстановление после рестарта контейнера;
- документация: BUG-записи, решения D054/D055, результаты проверок,
  заметка в OPERATIONS о требовании повторного restore.

- Сборка без ошибок и предупреждений (SDK 10.0.401, net10.0);

  физических путей;

  очистка только неактивных задач;

## Известные дефекты

Нет открытых дефектов продукта.
Это не означает, что приложение проверено.

Флейк тестовой инфраструктуры (2026-11-07, I14): при одном прогоне
`MoveEndpoint_QueuesAndCompletesMoveWithAntiforgery` упал с «Файл
конфигурации не найден». Тест меняет процессные переменные
`ConfigPath`/`DatabasePath`, а xUnit выполняет классы параллельно;
соседний тест может увидеть чужой/удалённый путь. Повторный прогон —
109/109. Это дефект изоляции тестов, не продукта; в I14 не исправлялся.

BUG-001 (исправлен 2026-11-07, I13)
  - серьёзность: критичная (весь интерактивный UI в контейнере);
  - симптом: в Docker `GET /_framework/blazor.web.js` → 404, Blazor circuit
    не подключается, кнопки/диалоги/меню не работают;
  - воспроизведение: `docker compose up --build`, открыть `/browse`;
  - причина: Dockerfile выполнял restore с одними csproj, затем
    `dotnet publish --no-restore`; манифест статических ресурсов терял
    JS фреймворка Blazor;
  - ожидаемое поведение: скрипт отдаётся 200, UI интерактивен;
  - затронутая итерация: Dockerfile с I01, выявлено в I13;
  - исправление: повторный `dotnet restore` после `COPY . .` (D054).

BUG-002 (исправлен 2026-11-07, I13)
  - серьёзность: средняя (UI-состояние расходилось с SQLite);
  - симптом: завершённая задача оставалась в «Активных», список файлов
    не обновлялся после copy/move до ручного refresh;
  - причина: уведомление, пришедшее во время выполняющегося refresh,
    отбрасывалось флагом `_refreshScheduled`;
  - исправление: цикл refresh с флагом `pending` — повторный проход при
    изменениях во время refresh (D055).

В S009 найден и исправлен дефект: в Production ошибки API перехватывались
generic exception handler раньше `ApiExceptionMiddleware` и возвращались как
`500` HTML вместо ProblemDetails. Причина — порядок middleware; исправление
покрыто тестом `ApiErrors_InProduction_KeepProblemDetailsContract`.

В S010 исправлен платформенный дефект теста symlink: на Linux рядом с `link`
находился `target`, а тест ожидал ровно одну запись. Это была ошибка теста,
а не продукта; проверка `unsupported` сохранена.

В S012 (I09) найден и исправлен дефект UI: `SelectedEntry` вычислялся через
`SingleOrDefault`, который бросает исключение при двух и более выбранных
объектах. Теперь переименование и удаление доступны только при ровно одном
выбранном объекте, а копирование/перемещение — для нескольких.

|---|---|---|
| D001 | .NET 10, Blazor Interactive Server | Единый серверный стек |
