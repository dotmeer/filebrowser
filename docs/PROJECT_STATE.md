## Текущая итерация: I08 — Исполнитель move

### Цель

Реализовать фоновый move с быстрым rename в одной файловой системе,
подтверждённым cross-device fallback copy + delete, безопасной публикацией,
честным частичным результатом и общим preflight согласно SPEC §10, §13, §16
и промпту I08 в SPEC §23.

### Сделано

- Добавлен `POST /api/tasks/move`: antiforgery, `202 Accepted`, id и
  `Location: /api/tasks/{id}`. Он использует тот же контракт `sources` +
  `destination`, что и copy.
- Общая механика copy/move вынесена в `FileTransferEngine`: preflight со сбором
  всех ошибок, scanning, регистрация временных объектов, потоковое копирование,
  публикация без перезаписи, cleanup, прогресс и безопасные ошибки.
- `CopyTaskExecutor` переведён на общий engine без изменения поведения copy;
  существующие copy-тесты проходят.
- `MoveTaskExecutor` для каждого источника сначала выполняет rename через
  `Directory.Move` в пределах одной файловой системы. Для файлов и каталогов
  это даёт быстрый путь без искусственной скорости.
- Cross-device fallback включается только при численно подтверждённом EXDEV
  (`HResult=18` на Linux). Другие `IOException` не запускают copy+delete.
  `File.Move` для move-задачи не используется, поскольку скрывает cross-device
  и может оставить частичный destination.
- Cross-device move: зарегистрированный `.filebrowser-*` → copy → публикация
  без перезаписи → удаление источника. Источник не удаляется до успешной
  публикации.
- Если удаление источника после публикации не удалось, назначение не
  откатывается; задача и элемент получают ошибку с явным указанием, что
  назначение создано, а источник мог сохраниться полностью или частично.
- Конфликт имени при move — ошибка задачи `name_conflict`, без HTTP 409 и без
  автосуффиксов; существующие данные сохраняются.
- Порядок источников остаётся ordinal по публичному пути; при первой
  фактической ошибке последующие верхнеуровневые объекты получают
  `not_processed`.
- Добавлены тесты move в одной файловой системе, конфликта имени,
  вложенности, сбора ошибок preflight, частичного результата, ошибки copy в
  cross-device ветке, ошибки удаления источника, endpoint move с antiforgery и
  без него, а также реального cross-device move файла и каталога на Linux tmpfs.

### Осталось

- UI панели задач и уведомлений не реализован — это граница I09.
- Реальный второй диск/NAS с двумя mounts не проверялся. Cross-device move

  повторить.
- Автоматическое продолжение move после рестарта не предусмотрено; активные
  задачи при старте переводятся в `interrupted`.

| D040 | Общая механика copy/move вынесена в `FileTransferEngine`; copy и move остаются отдельными исполнителями | Не дублировать preflight, временные объекты, публикацию, cleanup и прогресс; сохранить разные стратегии move |
