# Руководство пользователя

filebrowser — файловый менеджер для одного владельца или небольшой группы в **доверенной сети**. Не публикуйте его в интернете. Проект создан с помощью vibe coding и ИИ.

## Возможности и ограничения

Несколько корней и общее дерево, поиск по именам, создание папок и переименование; фоновые копирование, перемещение и безвозвратное удаление с прогрессом, отменой и историей; загрузка файлов без перезаписи, скачивание файла или потокового ZIP, предпросмотр изображений, PDF и текста (до 512 КиБ). Интерфейс доступен на русском и английском, поддерживает темы. Внешние изменения появляются после обновления.

Символические ссылки нельзя открывать или изменять; при скачивании папки ZIP пропускает ссылки после подтверждения. Специальные файлы не поддерживаются. Нет корзины, редактора, распаковки архивов, загрузки папок, докачки, групп, квот и аудит-лога. После перезапуска незавершённые задачи не продолжаются. Поиск ограничен 500 результатами и 60 секундами. При ошибке пакетной операции выполненные элементы не откатываются.

## Docker Compose

Образ: [`dotmeer/filebrowser`](https://hub.docker.com/r/dotmeer/filebrowser). На Linux создайте `config.yaml` и каталог `data` рядом с `compose.yaml`. Файлы в `data` должны быть доступны UID/GID контейнера (по умолчанию 1654); задайте другие значения в `user` и для `chown`, если необходимо.

`config.yaml`:

```yaml
workers: 2
uploads:
  maxFileBytes: 8589934592
roots:
  - name: files
    path: /data
```

`compose.yaml`:

```yaml
services:
  config-permissions:
    image: dotmeer/filebrowser:latest
    user: "0:0"
    entrypoint: ["/bin/sh", "-c", "chown -R 1654:1654 /config"]
    volumes:
      - config:/config
  filebrowser:
    image: dotmeer/filebrowser:latest
    user: "1654:1654"
    environment:
      AUTH_MODE: LOCAL
    ports:
      - "127.0.0.1:8080:8080"
    depends_on:
      config-permissions:
        condition: service_completed_successfully
    volumes:
      - config:/config
      - ./config.yaml:/config/config.yaml:ro
      - ./data:/data
volumes:
  config:
```

Запустите `docker compose up -d` и откройте `http://127.0.0.1:8080/`. Для доступа из локальной сети измените binding и ограничьте доступ средствами сети. Остановка — `docker compose down` без `-v`: удаление volume уничтожит БД. Для сборки из исходников клонируйте [репозиторий на GitHub](https://github.com/dotmeer/filebrowser) и используйте входящий в него Compose с `docker compose up --build`.

## Доступ и конфигурация

`AUTH_MODE` задаётся при запуске: `LOCAL` включает учётные записи, `ANONYMOUS` — доступ без входа ко всем корням, настройкам и общей истории. **Если переменная отсутствует, действует ANONYMOUS.** Пустое или неверное значение запрещено. При первом запуске LOCAL первый посетитель задаёт пароль `admin`; ограничьте доступ к серверу до завершения настройки. Admin управляет пользователями и правами на чтение или запись по корням; новый пользователь обязан сменить временный пароль. При переключении в ANONYMOUS сохранённые учётные записи остаются в БД, но вход больше не требуется.

YAML читается один раз при старте. `workers` — от 1 до 16, по умолчанию 2; `uploads.maxFileBytes` — положительный лимит файла в байтах, по умолчанию 8 ГиБ. Нужен хотя бы один корень: `name` соответствует `[a-z0-9][a-z0-9_-]{0,63}`, имена уникальны без учёта регистра, пути абсолютные и не пересекаются. Имя используется в ссылках и правах: его изменение меняет идентификатор корня. Пути в контейнере должны соответствовать mounts. Недоступный корень не мешает запуску и повторно проверяется при обращении; неверная конфигурация или недоступная БД останавливает запуск.

По умолчанию конфигурация — `/config/config.yaml`, БД — `app.db` рядом с ней; их можно изменить через `ConfigPath` и `DatabasePath`. Не размещайте конфигурацию и БД в доступном корне: администратор и анонимный пользователь могут видеть служебные файлы, а альтернативные пути через mounts или hardlinks не изолированы. Пути и права ОС не защищают от враждебного локального процесса, подменяющего файлы при проверке.

## Эксплуатация

Храните `/config` постоянно, SQLite — на локальной файловой системе, один экземпляр приложения на БД. Резервируйте YAML и БД при остановленном приложении, пользовательские файлы — отдельно; автоматического восстановления БД нет. После пересоздания контейнера ключи Data Protection теряются: старые сессии завершаются и требуется повторный вход; учётные записи сохраняются.

Восстановление пароля `admin` при остановленном приложении (пароль вводится в консоли):

```sh
docker compose stop filebrowser
docker compose run --rm -it filebrowser reset-admin-password
docker compose up -d filebrowser
```

`/health/live` и `/health/ready` отвечают при работе сервера, но не проверяют БД и корни. Логи выводятся в stdout в JSON; OTLP необязателен и включается стандартными переменными, например `OTEL_EXPORTER_OTLP_ENDPOINT`. За обратным прокси согласуйте лимиты и таймауты загрузок и ZIP; доверяйте forwarded-заголовкам только явно заданным прокси (`ForwardedHeaders__Enabled`, `ForwardedHeaders__KnownProxies__0`).

## Разработка

.NET 10, ASP.NET Core, Blazor Interactive Server, Minimal API, SQLite, YamlDotNet, OpenTelemetry и xUnit. Для проверки: `dotnet build`, `dotnet test`, `docker build -t filemanager .`, `docker compose config`. См. [архитектуру](SPEC.md) и [ручные сценарии](MANUAL_TEST_SCENARIOS.md). Полная ручная приёмка авторизации, в том числе переключения режимов и отзыва прав во время длительных операций, остаётся незавершённой; отдельной регрессии для `SQLITE_BUSY`/`SQLITE_LOCKED` нет.
