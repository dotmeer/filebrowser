# Архитектурные решения

Приложение предназначено для доверенной сети и доверенного хоста. Доступ ограничивается настроенными корнями и правами ОС; защиты от локального процесса, подменяющего компоненты пути между проверкой и открытием, нет. Сетевые ограничения и mounts — дополнительные границы доступа.

## Устройство

- Один серверный и один тестовый проект: .NET 10, ASP.NET Core, Blazor Interactive Server, Minimal API, SQLite, YamlDotNet, OpenTelemetry и xUnit. Без EF Core, CQRS, mediator, микросервисов и отдельного SignalR Hub.
- Blazor и HTTP используют общие прикладные сервисы; компоненты не вызывают HTTP собственного приложения. Содержимое файлов передаётся по обычному HTTP, не через circuit. Интерфейсы вводятся на реальных границах.
- Клиент адресует файл через root и относительный path. Общий resolver проверяет сегменты и все компоненты пути; symlink и специальные файлы не обходятся. Физические пути не раскрываются в DTO и HTTP-ошибках, содержимое файлов не логируется. Корни нельзя удалять, перемещать или переименовывать.
- Изменяющие HTTP-запросы требуют antiforgery; permissive CORS запрещён. LOCAL проверяет действующую сессию и права на сервере, включая операции открытого circuit и фоновые задачи. SQLite — источник истины о сессиях, правах и задачах; после reconnect состояние перечитывается.

## Файловые операции

- Конфликт имени — ошибка: перезапись и автоматические суффиксы запрещены. Публикация атомарна и без перезаписи; одной проверки Exists мало.
- Copy/move/delete принимают источники из одной папки в ordinal-порядке; полная предпроверка собирает ошибки до изменений. Исполнение прекращается на первой ошибке без отката завершённых объектов. Move удаляет источник только после публикации; copy+delete допустим только при подтверждённой cross-device ошибке.
- Удаление выполняется фоновой задачей через зарегистрированный временный артефакт; совпадение префикса само по себе не разрешает удаление. Регистрация оставшихся артефактов сохраняется при очистке истории и ошибках cleanup.
- Upload — отдельный raw HTTP POST на файл с Content-Length и antiforgery; временный файл зарегистрирован, при неуспехе очищается, публикация без перезаписи, ограничение задаётся `uploads.maxFileBytes`. Upload не занимает очередь worker. Отмена и отзыв прав проверяются до публикации.
- ZIP создаётся потоком без временного файла и сжатия; предпроверка проводится до ответа, ошибка после начала ответа обрывает соединение. Полный обход дерева не выполняется синхронно в UI-контексте.

## Хранение и эксплуатация

- SQLite использует параметризованные запросы, нумерованные миграции, короткие транзакции и отдельные соединения для конкурентных операций; файловый ввод-вывод не выполняется внутри длительной транзакции. Повреждённая или недоступная БД останавливает запуск, автоматического восстановления нет.
- Недоступный корень не останавливает сервер и проверяется при следующем обращении. Один экземпляр приложения использует БД на локальной ФС.
- OTLP необязателен и настраивается стандартными `OTEL_*`.
