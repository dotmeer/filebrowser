# Ручные тест-сценарии

Сценарии, которые нельзя полностью покрыть автоматическими тестами:
приёмка развёртывания на реальной среде и интерактивный браузерный UI
с WebSocket-сессией Blazor.

Автоматический suite проходит командой `dotnet test`; он не заменяет
проверки ниже.

## Приёмка развёртывания

Выполнить после развёртывания на новой среде (контейнер или локальный
запуск, тестовые каталоги, не пользовательские данные):

- [ ] `GET /healthz` → `200` с телом `{"status":"ok"}`;
- [ ] Открыть `/browse`: ленивое дерево, список каталога, breadcrumbs,
      прямой URL `/browse?root=...&path=...`;
- [ ] Раскладка «Каталоги | Файлы | Задачи»: перетаскивание обоих
      разделителей меняет ширину панелей, панели не сжимаются меньше
      минимальных (кнопки и названия не обрезаются);
- [ ] Бургер-меню в правом верхнем углу: пункт «Настройки» открывает
      `/settings`, меню закрывается кликом вне него;
- [ ] Кнопки действий: «Обновить» первая, доступные контрастные,
      недоступные бледные; «Удалить» красная; при узкой панели кнопки
      переносятся на новую строку, не вылезая за границы;
- [ ] Создать папку, переименовать её, удалить с подтверждением;
      повторное создание существующего имени завершается ошибкой,
      данные не перезаписаны;
- [ ] Выбрать ровно один файл и скачать его; проверить Range через
      `curl -H "Range: bytes=0-4" http://127.0.0.1:8080/api/fs/download?...`
      → `206 Partial Content`;
- [ ] Скопировать и переместить один и несколько объектов; проверить
      активные задачи, прогресс, скорость и счётчики; конфликт имён
      даёт ошибку задачи без перезаписи данных;
- [ ] Перезапустить приложение: активные задачи стали `interrupted`,
      после повторного открытия `/browse` состояние перечитано
      из SQLite;
- [ ] Очистить историю: активные задачи и файлы не изменились;
- [ ] Проверить UID процесса в контейнере:
      `docker exec <container> id -u` → не root (1654 по умолчанию);
- [ ] Логи контейнера в JSON; `traceId` из ProblemDetails ошибки
      найден в логах;
- [ ] При заданном `OTEL_EXPORTER_OTLP_ENDPOINT`: в Collector видны
      service `dotmeer.filebrowser`, span `filebrowser.task.execute`
      и метрики `dotmeer.filebrowser.tasks.*`.

## UI-сценарии (браузер)

2026-11-07 (I13): интерактивные сценарии пройдены в Linux-контейнере
через реальный браузер (расширение browse): бургер-меню и «Настройки»,
разделители и минимальные ширины, состояния кнопок, mkdir/rename/delete,
конфликт имён, download, copy/move с автообновлением, очистка истории,
контекстное меню, пустая папка, прямые URL, узкое окно, рестарт
контейнера и reconnect. Результаты — в `docs/PROJECT_STATE.md` (I13).
Сценарии ниже остаются для повторной приёмки на новых средах.

- [ ] Пустой каталог и ошибка недоступного/исчезнувшего каталога
      показывают корректные состояния в браузере (SSR-состояния
      проверены WebApplicationFactory-тестами).
- [ ] Linux-контейнер и мобильные/узкие размеры окна вне
      Windows-браузера (проверено только узкое окно на Windows).
- [ ] Открыть окно выбора папки назначения для copy/move: текущая
      папка, исходные объекты и их потомки показаны недоступными.
- [ ] Поставить copy/move из UI и увидеть карточку задачи без ручного
      обновления страницы.
- [ ] Наблюдать scanning/running в карточке активной задачи:
      неопределённый прогресс, проценты, скорость и счётчики.
- [ ] Выйти со страницы `/browse` и вернуться: подписка снимается,
      состояние перечитывается из SQLite без потери задач.
- [ ] Разорвать и восстановить соединение Blazor (остановить и
      запустить сервер): панель перечитывает состояние из SQLite;
      после перезапуска активные задачи отображаются как `interrupted`.
- [ ] После завершения copy/move в текущую папку файловый список
      обновляется без ручной кнопки «Обновить».
- [ ] Нажать «Очистить историю»: требуется подтверждение, активные
      задачи остаются в списке.
