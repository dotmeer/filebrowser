# filebrowser

Self-hosted веб-файлменеджер: просмотр и управление файлами через браузер.
Работает только с каталогами, явно перечисленными в конфигурации; каждый
каталог отображается отдельным корнем.

Статус: MVP реализован и принят; проект развивается как существующий
self-hosted production-ready продукт.

> **Важно:** авторизации нет. Приложение рассчитано на одного владельца
> или небольшую группу пользователей в доверенной домашней сети.
> Не выставляйте его в интернет и не полагайтесь на него как на защиту
> от враждебных клиентов в сети.

## Что умеет

- Несколько корней файловой системы с ленивым деревом каталогов;
- просмотр содержимого папок, навигация через URL (`/?root=...&path=...`);
- создание папки, переименование, безвозвратное удаление одного или
  нескольких объектов (фоновой задачей);
- мультивыбор и фоновое копирование/перемещение между корнями;
- очередь задач с прогрессом, скоростью и историей в SQLite;
- скачивание одного файла с поддержкой Range;
- предпросмотр изображений, PDF и текстовых файлов (не более первых
  512 КиБ текста) в модальном окне — двойной клик по имени файла или
  пункт контекстного меню «Предпросмотр»; видео и аудио не предпросматриваются;
- поиск по именам объектов (подстрока без учёта регистра, glob-фильтр
  расширений) с переходом к найденному объекту и показом пути к нему;
- виртуальный корень «Все корни» — объединённое read-only представление
  всех подключенных корней (просмотр, поиск по всем корням, скачивание);
  изменяющие операции внутри него недоступны;
- светлая, тёмная и системная тема оформления (выбор хранится в браузере);
- интерфейс на английском (по умолчанию) и русском; язык выбирается
  в «Настройках» и хранится на сервере в SQLite, общий для всех клиентов;
- Docker-запуск от непривилегированного пользователя;
- JSON-логи, traceId в ошибках, OpenTelemetry tracing/metrics;
- автоматические тесты критичной логики, включая Linux-сценарии.

## Что не умеет (границы продукта)

- Авторизация, пользователи и роли;
- загрузка файлов на сервер;
- скачивание папок и наборов объектов (ZIP);
- предпросмотр видео и аудио, корзина (не планируются);
- symlink и специальные файлы не поддерживаются;
- конфликт имён — всегда ошибка, автосуффиксы не подбираются.

Подробные границы и правила — в `docs/SPEC.md`,
направления развития — в `docs/ROADMAP.md`.

## Требования

- [.NET SDK 10](https://dotnet.microsoft.com/download/dotnet/10.0)
  (версия зафиксирована в `global.json`);
- Docker — для запуска в контейнере (опционально).

## Быстрый запуск локально

Создайте конфигурацию из примера и запустите:

```powershell
Copy-Item config.example.yaml config.yaml
$env:ConfigPath = (Resolve-Path config.yaml).Path
dotnet run --project src/dotmeer.filebrowser
```

Откройте `http://127.0.0.1:8080/browse`.

Проверка работоспособности:

```text
GET /health/live  → 200 Healthy
GET /health/ready → 200 Healthy
```

## Запуск через Docker Compose

Compose — основной способ запуска. Перед первым запуском создайте
`config.yaml`, затем:

```text
docker compose up --build
```

Приложение будет доступно на `http://127.0.0.1:8080`.
Остановка — `docker compose down`.

По умолчанию порт публикуется только на loopback. Для доступа из LAN
измените binding в `compose.yaml` на `8080:8080` и обеспечьте сетевые
ограничения самостоятельно.

Однострочный запуск без Compose (предварительно соберите образ:
`docker build -t filemanager .`):

```text
docker run --rm -p 127.0.0.1:8080:8080 -v ./config.yaml:/config/config.yaml:ro -v ./data:/data filemanager
```

## Конфигурация

Минимальный `config.yaml`:

```yaml
workers: 2

roots:
  - name: files
    path: /data
```

- конфигурация читается один раз при старте, hot reload нет;
- `workers` — от 1 до 16, по умолчанию 2;
- имя корня — публичный идентификатор (`[a-z0-9][a-z0-9_-]{0,63}`),
  его смена делает старые ссылки нерабочими;
- корни не должны пересекаться друг с другом;
- можно назначить даже `/` или каталог, содержащий `config.yaml`
  и `app.db`; такие файлы будут видны и доступны операциям на страх
  и риск владельца;
- недоступный корень не останавливает запуск — он помечается
  и проверяется заново при обращении;
- невалидный конфиг останавливает запуск с понятной ошибкой.

> **Внимание:** приложение не защищает служебные файлы, попавшие в корень.
> Удаление или повреждение `app.db` разрушает историю задач и может
> остановить запуск; удаление `config.yaml` влияет на следующие запуски.

Пути в контейнере: `/config/config.yaml` (read-only mount),
`/config/app.db` (SQLite), корни данных — отдельные mounts
(`./data` → `/data` в примере).

SQLite создаётся рядом с активным `ConfigPath` (по умолчанию
`/config/app.db`). Повреждённая БД останавливает запуск;
автовосстановления и автобэкапов нет. Резервируйте содержимое `/config`
средствами хоста только при остановленном приложении.

`config.yaml` в Git не коммитится.

## Использование

- `/browse` — раскладка из трёх панелей: дерево корней слева, таблица
  текущей папки в центре, панель задач справа; панели разделены
  перетаскиваемыми разделителями с ограничением минимальной ширины;
  над таблицей — breadcrumbs и действия; дерево загружается лениво;
- выбор строк — checkbox; переименовать/удалить можно ровно один объект,
  скачать — ровно один файл;
- предпросмотр: двойной клик по имени файла изображения, PDF или текста
  (или пункт «Предпросмотр» контекстного меню) открывает модальное окно;
  работает и в виртуальном корне; кнопка «Скачать» внутри окна ведёт на
  обычное скачивание;
- «Копировать»/«Переместить» открывают выбор папки назначения и ставят
  фоновую задачу; конфликт имён не перезаписывает данные;
- панель задач показывает активные задачи и историю, позволяет очистить
  историю (только неактивные задачи, файлы не затрагиваются);
- «Настройки» (`/settings`) позволяют выбрать светлую, тёмную или
  системную тему; выбор хранится в браузере и не входит в `config.yaml`;
  там же выбирается язык интерфейса (английский по умолчанию или русский);
  язык хранится на сервере в SQLite и применяется после сохранения;
  кнопка «Назад» возвращает на предыдущую страницу;
- поиск: строка над таблицей ищет подстроку в именах объектов текущей
  папки (рекурсивно, без учёта регистра); в результатах под именем
  показывается родительский путь; клик по результату открывает каталог,
  файл — его родительскую папку с подсветкой; результат ограничен
  500 объектами и бюджетом времени 60 с — при усечении показывается
  уведомление; недоступные корни не участвуют в поиске и перечисляются
  в уведомлении;
- виртуальный корень «Все корни» в дереве слева: центральная панель
  показывает подключенные корни как папки (недоступные — неактивными);
  доступны просмотр, поиск по всем корням и скачивание; создание,
  переименование, удаление и копирование/перемещение внутри него
  недоступны;
- внешние изменения файлов появляются после кнопки «Обновить».

## HTTP-интерфейс

Внешний изменяющий API не предоставляется: все операции выполняются
через UI (Blazor вызывает прикладные сервисы напрямую). Наружу открыты
только два вида эндпоинтов:

- скачивание файла: `GET /api/fs/download?root=...&path=...`
  (поддерживается виртуальный корень `AllRoots`, Range-запросы);
- предпросмотр файла: `GET /api/fs/preview?root=...&path=...`
  (изображения/PDF/текст, `inline`; тип вне списка →
  `415/preview_not_supported`);
- health-checks: `GET /health/live`, `GET /health/ready`
  (для liveness/readiness-проб оркестратора).

Полный контракт — в `docs/SPEC.md` §16 и §5.3.

## Наблюдаемость

Логи пишутся в stdout в JSON; ошибки содержат `traceId`.
OpenTelemetry tracing/metrics включены, экспорт в OTLP Collector —
опционально через стандартные `OTEL_*` переменные. Подробности —
в `docs/OPERATIONS.md`.
