# filebrowser

Self-hosted веб-файлменеджер на .NET 10 и Blazor Server для доверенной сети.
Авторизации нет: не публикуйте приложение в интернете. Доступны только
каталоги, перечисленные в конфигурации.

## Возможности

- Несколько корней, ленивое дерево и объединённый узел «Все корни».
- Создание папок, переименование, массовое безвозвратное удаление.
- Фоновые copy/move/delete, прогресс, отмена и история в SQLite.
- Скачивание файла или выбранных объектов одним потоковым ZIP.
- Загрузка файлов кнопкой или перетаскиванием; без перезаписи существующих.
- Предпросмотр изображений, PDF и первых 512 КиБ текстового файла.
- Поиск по именам, прямые ссылки, английский/русский язык и темы оформления.
- Docker, JSON-логи и опциональный экспорт OpenTelemetry.

Нет пользователей/ролей, загрузки папок, докачки, поддержки symlink/спецфайлов.
Корзина, видео/аудиопредпросмотр и pause/resume не планируются.
Известные проблемы и результаты проверок — в [состоянии проекта](docs/PROJECT_STATE.md).

## Запуск через Docker Compose

Основной вариант — Linux-контейнер. Создайте `config.yaml` из
`config.example.yaml` и каталог `data`, затем:

```text
docker compose up --build
```

Адрес: `http://127.0.0.1:8080/`. Остановка: `docker compose down`
(без `-v`, чтобы сохранить БД). Корень примера — `./data` → `/data`,
SQLite хранится в постоянном volume `config`, YAML монтируется read-only.

Для LAN-доступа явно измените binding в `compose.yaml` на `8080:8080`
и обеспечьте сетевые ограничения. UID/GID задаются переменными
`FILEBROWSER_UID` / `FILEBROWSER_GID` (по умолчанию 1654).

## Локальный запуск

Нужен .NET SDK 10, политика версии — в `global.json`.
В YAML задайте абсолютные пути **локальной** файловой системы.
Например, для PowerShell:

```powershell
Copy-Item config.example.yaml config.yaml
# Отредактируйте roots[].path в config.yaml перед запуском.
$env:ConfigPath = (Resolve-Path config.yaml).Path
dotnet run --project src/dotmeer.filebrowser --no-launch-profile --urls http://127.0.0.1:8080
```

`GET /health/live` и `/health/ready` отвечают `200 Healthy`, когда приложение
отвечает; отдельной проверки доступности SQLite в readiness сейчас нет.

## Конфигурация

```yaml
workers: 2
uploads:
  maxFileBytes: 8589934592   # необязательно, по умолчанию 8 ГиБ
roots:
  - name: files
    path: /data
```

- YAML читается при старте; изменения требуют перезапуска.
- `workers`: 1–16, по умолчанию 2; `uploads.maxFileBytes`: положительный
  предел одного файла в байтах.
- Нужен хотя бы один корень. Имя: `[a-z0-9][a-z0-9_-]{0,63}`, уникально
  без учёта регистра. Смена имени ломает старые ссылки.
- Пути абсолютные, корни не совпадают/не вложены друг в друга.
- Недоступный корень не останавливает приложение; невалидный YAML или БД —
  останавливают. Автовосстановления БД нет.
- `ConfigPath` по умолчанию `/config/config.yaml`; `DatabasePath` — `app.db`
  рядом с активным ConfigPath. SQLite должна находиться на локальной ФС.

Корнем можно назначить `/` или каталог со служебными файлами, но общей
изоляции этих файлов нет. Фоновое удаление защищает активную конфигурацию
и БД; переименование/перемещение могут нарушить работу приложения.
Резервируйте `/config` при остановленном приложении. `config.yaml` не коммитится.

## Использование

Рабочая страница — `/`, прямая ссылка: `/?root=files&path=folder`.
Выбор — checkbox. Переименование требует одного объекта, удаление допускает
несколько. Одна кнопка «Скачать» отдаёт файл напрямую, папку/набор — ZIP.
В списке «Все корни» можно скачать один выбранный корень, но не несколько.
Изменения на верхнем уровне списка корней запрещены; внутри корня доступны.

Поиск рекурсивный по подстроке имени, до 500 результатов и 60 с; операции
над результатом доступны после перехода в его папку. Внешние изменения
файлов появляются после «Обновить». Предпросмотр — двойной клик/контекстное меню.

В `/settings` тема сохраняется в браузере, язык — на сервере для всех клиентов
и применяется после перезагрузки. Кнопка «✕» возвращает на `/`.

## HTTP и эксплуатация

Файловые маршруты: `GET /api/fs/download`, `/api/fs/zip`, `/api/fs/preview`,
`/api/fs/upload/check`; `POST /api/fs/upload`. Загрузка — сырое тело одного
файла, обязательные Content-Length и antiforgery-заголовок `X-CSRF-TOKEN`.
Необязательный `uploadId` связывает загрузку с задачей; отмена выполняется
через Blazor-сервис задач. Если браузер теряет ответ upload, окно загрузки
сверяет итог с задачей через Blazor; сам обрыв не считается отменой.
Остальные изменения — через Blazor-сервисы,
внешнего API для них нет.
Полный контракт — [SPEC §16](docs/SPEC.md#16-http-интерфейс).

Логи — JSON в stdout, ошибки содержат traceId. OTLP включается стандартными
`OTEL_*`. Docker, прокси и резервное копирование — в [OPERATIONS](docs/OPERATIONS.md).
