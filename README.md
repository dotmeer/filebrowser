# filebrowser

Self-hosted веб-файлменеджер на .NET 10 и Blazor Server для доверенной сети.
Доступны только каталоги, перечисленные в конфигурации. Режим доступа
задаётся переменной `AUTH_MODE`: `ANONYMOUS` (по умолчанию, без входа) или
`LOCAL` (локальные учётные записи). Не публикуйте приложение в интернете.

## Возможности

- Несколько корней, ленивое дерево и объединённый узел «Все корни».
- Локальные учётные записи, права по корням и страница «Пользователи».
- Создание папок, переименование, массовое безвозвратное удаление.
- Фоновые copy/move/delete, прогресс, отмена и история в SQLite.
- Скачивание файла или выбранных объектов одним потоковым ZIP.
- Загрузка файлов кнопкой или перетаскиванием; без перезаписи существующих.
- Предпросмотр изображений, PDF и первых 512 КиБ текстового файла.
- Поиск по именам, прямые ссылки, английский/русский язык и темы оформления.
- Docker, JSON-логи и опциональный экспорт OpenTelemetry.

В `LOCAL` обычные учётные записи работают с файлами в пределах выданных прав;
управление учётками доступно только администратору. Нет групп, квот, загрузки
папок, докачки, поддержки symlink/спецфайлов и аудит-лога. Корзина,
видео/аудиопредпросмотр и pause/resume не планируются.
Известные проблемы и результаты проверок — в [состоянии проекта](docs/PROJECT_STATE.md).

## Режимы доступа

`AUTH_MODE` читается при старте. Отсутствие переменной означает `ANONYMOUS`;
допустимы `ANONYMOUS` и `LOCAL` (регистр не важен). Пустое или неизвестное
значение останавливает запуск с понятной ошибкой.

- `ANONYMOUS` — действующее поведение без входа: анонимному посетителю
  доступны все настроенные корни, настройки и общая история. Управление
  учётками недоступно, сохранённые учётные записи и сессии не изменяются.
- `LOCAL` — локальные учётные записи и cookie-сессии. Пока в SQLite нет
  `admin`, первый посетитель задаёт ему пароль через форму первичной
  настройки. Пароля по умолчанию, приглашения и саморегистрации нет.
  Обычная учётная запись входит с временным паролем, должна задать отличный от
  него пароль и затем работает с файлами в пределах выданных прав. Страница «Пользователи»
  доступна только `admin`.

Смысл переключения: `ANONYMOUS` снова открывает анонимному посетителю все
корни и всю историю. Учётные записи при этом сохраняются в SQLite; после
возврата в `LOCAL` владелец входит в уже созданную учётку `admin`.

## Права на корни

Права обычной учётной записи хранятся в SQLite по имени корня: `read`,
`write` или отсутствие записи (нет доступа). `read` разрешает листинг, дерево,
поиск, предпросмотр, скачивание файла и ZIP. `write` дополнительно разрешает
создание папки, переименование, upload/check, upload, удаление, а также
copy/move с этим корнем на любой стороне. `admin` и `ANONYMOUS` имеют полный
доступ. Новое имя корня прав автоматически не получает; повторное имя корня
означает тот же корень для прав.

`AllRoots` показывает только доступные корни. При входе без `root` выбирается
первый видимый корень. Прямая ссылка на недоступный корень даёт безопасный
отказ, а скрытые по правам корни не попадают в результаты и в список
`unavailableRoots`.

Сохранение прав на странице пользователей заменяет их для всех текущих корней:
пропущенное поле или «нет доступа» снимает право. Права корней, временно
отсутствующих в конфигурации, сохраняются в SQLite и возвращаются при
повторном появлении того же имени.

Права выдаёт администратор на странице «Пользователи» (пункт меню `admin`).
Там же создаётся обычная учётка с временным паролем, меняются права, пароль
сбрасывается и учётка удаляется. Временный пароль разрешает только смену
пароля и выход. Отсутствие права — «нет доступа»; новое имя корня прав
автоматически не получает. Изменения применяются к следующему действию.
Встроенную `admin` нельзя удалить, переименовать, понизить или сбросить через
страницу; её пароль меняется ей самой или локальной командой восстановления.
После удаления учётки и повторного создания того же логина выдаётся новый
внутренний ID, поэтому старые задачи новая учётка не видит.

## Служебные каталоги в LOCAL

Если `ConfigPath` или `DatabasePath` находятся внутри настроенного корня,
непосредственный родительский каталог каждого файла закрывается для обычных
учётных записей целиком. Если файл лежит прямо в корне, обычной учётке не
виден весь корень. Разные каталоги защищаются независимо; `admin` сохраняет
к ним доступ. Закрытый каталог и потомки отсутствуют в листинге, дереве,
поиске и выборе назначения; рекурсивный ZIP, copy/move/delete с таким предком
и переименование предка отклоняются. Соседний разрешённый каталог остаётся
доступен для навигации и создания/загрузки.

Защита не распространяется на созданные администратором копии БД и
альтернативные пути через host aliases, mounts или hardlink: конфигурация
NAS считается доверенной.

Compose (`environment` сервиса `filebrowser`):

```yaml
    environment:
      AUTH_MODE: LOCAL
```

Локальный запуск (PowerShell):

```powershell
$env:AUTH_MODE = "LOCAL"
```

Восстановление пароля `admin` при остановленном приложении (пароль вводится
с консоли, аргументом командной строки не передаётся):

```text
docker compose stop filebrowser
docker compose run --rm -it filebrowser reset-admin-password
```

```powershell
$env:ConfigPath = (Resolve-Path config.yaml).Path
# $env:DatabasePath = ...   # если БД вынесена из каталога ConfigPath
dotnet run --project src/dotmeer.filebrowser --no-launch-profile -- reset-admin-password
```

Команда меняет пароль только встроенной `admin` и отзывает её сессии. После
пересоздания контейнера учётные записи остаются в volume, но ключи Data
Protection не сохраняются: старые cookie перестают действовать, нужен
повторный вход.


## Запуск через Docker Compose

Основной вариант — Linux-контейнер. Создайте `config.yaml` из
`config.example.yaml` и каталог `data`, затем:

```text
docker compose up --build
```

Адрес: `http://127.0.0.1:8080/`. Остановка: `docker compose down`
(без `-v`, чтобы сохранить БД). Корень примера — `./data` → `/data`,
SQLite хранится в постоянном volume `config`, YAML монтируется read-only.

Для LAN-доступа явно измените binding в `compose.yaml` на `8080:8080`
и обеспечьте сетевые ограничения. UID/GID задаются переменными
`FILEBROWSER_UID` / `FILEBROWSER_GID` (по умолчанию 1654).

## Локальный запуск

Нужен .NET SDK 10, политика версии — в `global.json`.
В YAML задайте абсолютные пути **локальной** файловой системы.
Например, для PowerShell:

```powershell
Copy-Item config.example.yaml config.yaml
# Отредактируйте roots[].path в config.yaml перед запуском.
$env:ConfigPath = (Resolve-Path config.yaml).Path
dotnet run --project src/dotmeer.filebrowser --no-launch-profile --urls http://127.0.0.1:8080
```

`GET /health/live` и `/health/ready` отвечают `200 Healthy`, когда приложение
отвечает; отдельной проверки доступности SQLite в readiness сейчас нет.

## Конфигурация

```yaml
workers: 2
uploads:
  maxFileBytes: 8589934592   # необязательно, по умолчанию 8 ГиБ
roots:
  - name: files
    path: /data
```

- YAML читается при старте; изменения требуют перезапуска.
- `workers`: 1–16, по умолчанию 2; `uploads.maxFileBytes`: положительный
  предел одного файла в байтах.
- Нужен хотя бы один корень. Имя: `[a-z0-9][a-z0-9_-]{0,63}`, уникально
  без учёта регистра. Смена имени ломает старые ссылки.
- Пути абсолютные, корни не совпадают/не вложены друг в друга.
- Недоступный корень не останавливает приложение; невалидный YAML или БД —
  останавливают. Автовосстановления БД нет.
- `ConfigPath` по умолчанию `/config/config.yaml`; `DatabasePath` — `app.db`
  рядом с активным ConfigPath. SQLite должна находиться на локальной ФС.
- `AUTH_MODE` — переменная окружения, не поле YAML; допустимы `ANONYMOUS`
  и `LOCAL`. YAML, binding и mounts от режима не зависят.

Корнем можно назначить `/` или каталог со служебными файлами. В `LOCAL` для
обычных учётных записей родительские каталоги активных `ConfigPath` и
`DatabasePath` внутри корня скрываются; если файл лежит прямо в корне, корень
целиком доступен только `admin`. Общей изоляции для `ANONYMOUS` и
альтернативных путей нет. Фоновое удаление защищает активную конфигурацию
и БД; переименование/перемещение могут нарушить работу приложения.
Резервируйте `/config` при остановленном приложении. `config.yaml` не коммитится.

## Использование

Рабочая страница — `/`, прямая ссылка: `/?root=files&path=folder`.
Выбор — checkbox. Переименование требует одного объекта, удаление допускает
несколько. Одна кнопка «Скачать» отдаёт файл напрямую, папку/набор — ZIP.
В списке «Все корни» можно скачать один выбранный корень, но не несколько.
Изменения на верхнем уровне списка корней запрещены; внутри корня доступны.

Поиск рекурсивный по подстроке имени, до 500 результатов и 60 с; операции
над результатом доступны после перехода в его папку. Внешние изменения
файлов появляются после «Обновить». Предпросмотр — двойной клик/контекстное меню.

В `/settings` тема сохраняется в браузере, язык — на сервере для всех клиентов
и применяется после перезагрузки. В `LOCAL` глобальный язык меняет только
`admin`; остальные учётные записи видят действующий язык и могут менять тему.
В `ANONYMOUS` язык доступен без входа. Кнопка «✕» возвращает на `/`.

## HTTP и эксплуатация

Файловые маршруты: `GET /api/fs/download`, `/api/fs/zip`, `/api/fs/preview`,
`/api/fs/upload/check`; `POST /api/fs/upload`. Загрузка — сырое тело одного
файла, обязательные Content-Length и antiforgery-заголовок `X-CSRF-TOKEN`.
Необязательный `uploadId` связывает загрузку с задачей; отмена выполняется
через Blazor-сервис задач. Если браузер теряет ответ upload, окно загрузки
сверяет итог с задачей через Blazor; сам обрыв не считается отменой.
Остальные изменения — через Blazor-сервисы,
внешнего API для них нет.

В `LOCAL` файловый HTTP без действующей сессии отвечает `401`, а учётке без
допуска (временный пароль, отозванная запись) или без прав на запрошенный
корень/служебную ветку — `403`; оба ответа — ProblemDetails без редиректа на
HTML. Вход, выход и смена пароля — `POST /auth/login`, `/auth/setup`,
`/auth/logout`, `/auth/change-password` с antiforgery. Полный контракт —
[SPEC §16](docs/SPEC.md#16-http-интерфейс).

Логи — JSON в stdout, ошибки содержат traceId. OTLP включается стандартными
`OTEL_*`. Docker, прокси и резервное копирование — в [OPERATIONS](docs/OPERATIONS.md).
