# Инструкции для агента

- Перед работой проверь `git status`, прочитай `docs/SPEC.md`, изучи код и тесты задачи; при изменении поведения прочитай пользовательскую документацию.
- Код и тесты показывают фактическое поведение; документация не доказывает работоспособность. Не разрешай молча противоречия о данных, безопасности и API.
- Выполняй только порученное, сохраняй пользовательские изменения, не создавай commit, push или подагентов без поручения. Не применяй destructive Git-команды.
- Соблюдай архитектурные решения из SPEC. Изменения поведения сопровождай регрессионными тестами с реальной ФС/SQLite или HTTP-хостом, когда применимо. Linux-сценарии проверяй в Linux.
- Запускай применимые проверки: `dotnet build`, `dotnet test`, `docker build -t filemanager .`, `docker compose config`. Сообщай, что не запускалось и почему; не ослабляй проверки ради успешного результата.
- При изменении пользовательского поведения или конфигурации обновляй обе инструкции `docs/README.en.md` и `docs/README.ru.md`; при изменении архитектуры — SPEC. Новые зависимости обосновывай.
- Документация и ответы — на русском, кроме английской пользовательской документации; имена кода и API — на английском.
